# VOD Recorder 사용 설명서

설치는 [설치 안내](INSTALL.md)를, 쓰기 전에 알아 둘 점은 [주의사항](CAUTIONS.md)을 먼저 읽어 주십시오.

## 1. 처음 설정

1. 서버를 처음 띄우면 로그에 **첫 설정 코드**가 한 번 찍힙니다. 컨테이너라면 `docker logs vodrecorder`로 봅니다. 놓쳤으면 `vod-recorder account setup-code`(컨테이너 안에서는 `python -m live_recorder account setup-code`)로 다시 봅니다.
2. 브라우저로 서버 주소를 열면 첫 설정 화면이 나옵니다. 사용자 이름, 비밀번호, 설정 코드를 넣어 관리자 계정을 만듭니다. 계정은 하나입니다.
3. 계정을 만들기 전에는 보기 전용으로 돕니다. 채널 추가나 설정 변경은 계정을 만든 뒤에 할 수 있습니다.

**설정 코드를 받는 까닭**: 첫 설정 화면은 로그인 없이 열립니다. 코드가 없으면 그 주소에 먼저 접속한 사람이 관리자 계정을 만들 수 있습니다. 코드는 서버의 로그와 명령줄에서만 볼 수 있어서, 서버를 설치한 사람만 계정을 만들 수 있게 합니다. 계정을 만들고 나면 코드는 쓰이지 않습니다.

**코드 없이 계정 만들기**: 서버를 처음 띄울 때 환경변수 `LIVE_RECORDER_ADMIN_USER`와 `LIVE_RECORDER_ADMIN_PASSWORD`를 주면 그 값으로 계정이 만들어지고 첫 설정 화면을 거치지 않습니다. 계정이 만들어진 뒤에는 두 환경변수를 지우십시오. 명령줄의 `vod-recorder account create <이름>`으로도 만들 수 있습니다.

**설정 코드 끄기**: 환경변수 `LIVE_RECORDER_SETUP_CODE=off`를 주면 첫 설정 화면이 코드를 묻지 않습니다. 이때는 계정을 만들기 전까지 그 주소에 접속할 수 있는 누구나 관리자 계정을 만들 수 있습니다. 서버가 내부망 안에만 열려 있을 때만 쓰고, 띄운 뒤 바로 계정을 만드십시오. 서버는 이 상태로 시작할 때마다 로그에 경고를 남깁니다.

비밀번호는 설정 화면의 "비밀번호 변경"이나 `vod-recorder account passwd`로 바꿉니다. 바꾸면 열려 있던 로그인이 모두 끊깁니다. 화면에서 "접근 키도 모두 폐기"를 고르면 발급한 접근 키도 함께 폐기됩니다. 명령줄로 계정을 지우면 키도 모두 폐기되며, 계정이 없는 동안에는 키를 받지 않습니다.

## 2. 화면 구성

| 탭 | 하는 일 |
|---|---|
| 채널 | 녹화할 채널을 등록하고 상태를 봅니다. 최근 7일의 녹화 시간표와 녹화 목록이 있습니다 |
| 기록 | 지난 녹화의 시작·종료 시각, 끝난 까닭, 파일 크기를 봅니다 |
| 다시보기 | 주소로 받기, 채널 목록에서 골라 받기, 다운로드 작업 목록 (확장을 켰을 때 보입니다) |
| 파일 | 녹화 폴더의 파일을 다룹니다 |
| 쿠키 | 플랫폼별 로그인 쿠키를 넣고 확인합니다 |
| 로그 | 서버 로그를 텍스트로 봅니다. 아래가 새 줄이고, 새 줄을 자동으로 따라갑니다. 수준·채널·글자로 거릅니다 |
| 설정 | 녹화, 알림, 플랫폼, 확장, 접근 키, 로그 내려받기 |

화면 색은 밝게, 어둡게, 자동 가운데 고릅니다. 좁은 화면(휴대전화)에서도 쓸 수 있습니다.

## 3. 채널 등록과 녹화

### 채널 추가

채널 탭의 "채널 추가"에 채널 주소나 `@핸들`을 넣습니다. 플랫폼은 주소를 보고 알아냅니다.

| 플랫폼 | 넣는 값의 예 |
|---|---|
| 치지직 | `https://chzzk.naver.com/<채널 ID 32자리>` 또는 채널 ID |
| 유튜브 | `https://www.youtube.com/@이름` 또는 채널 주소 |
| 씨미 | `https://ci.me/@핸들` |

유튜브와 씨미는 설정에서 먼저 켜야 합니다([7. 플랫폼 켜기](#7-플랫폼-켜기-유튜브씨미)).

채널마다 저장 폴더(녹화 폴더 아래의 폴더 이름), 화질(기본 `best`), 파일 형식(`.mp4` 등), 영상 코덱 우선순위, 자동 녹화 여부를 정합니다.

### 영상 코덱 (치지직)

> **주의.** 0.1.4에서 새로 들어간 기능이고, 실제 방송으로 검증한 시간이 짧습니다. 중요한 녹화는 결과 파일이 끝까지 재생되는지 직접 확인해 주십시오. 무엇을 확인했고 무엇을 알아채지 못하는지는 이 절 끝의 "검증 범위와 한계"에 적었습니다.

치지직의 일부 채널은 1080p를 H.264와 HEVC(H.265) 두 가지로 함께 내놓습니다. 채널의 "영상 코덱 우선순위"로 어느 쪽을 받을지 정합니다.

| 값 | 동작 |
|---|---|
| H.264 우선 (기본) | H.264가 있으면 H.264를 받습니다 |
| HEVC 우선 | HEVC가 있으면 HEVC를 받습니다 |
| AV1 우선 | AV1이 있으면 AV1을 받습니다 |
| 방송이 주는 대로 | 방송이 먼저 내놓은 것을 받습니다 |

- 고른 코덱이 방송에 없으면 있는 코덱으로 녹화합니다. 녹화를 거부하지 않습니다.
- 한 파일에는 한 가지 코덱만 담습니다. 녹화 중에 받던 코덱이 사라지거나 다른 코덱으로 바뀌면 그 자리에서 파일을 나누고 새 파일로 이어 받습니다. 두 파일을 하나로 합치지는 않습니다.
- 파일이 나뉘면 텔레그램으로 "녹화 중 영상 코덱 바뀜"을 알리고, 기록 화면의 메모에 앞뒤 코덱을 남깁니다.
- 타임머신으로 받는 중이면 나뉜 두 파일 사이에 빠지는 구간이 없습니다. 일반 수신은 새 파일을 여는 몇 초 사이에 짧은 구간이 빠질 수 있고, 그때는 빈 시간을 메모에 적습니다.
- 받은 코덱은 기록 화면에 파일마다 보입니다. H.264가 아니면 화질 표시 뒤에도 붙습니다(예: `1080p60 HEVC`).
- 다시 인코딩하지 않으므로 HEVC로 받은 파일은 HEVC 그대로입니다. 재생기나 편집 도구가 HEVC를 지원하는지 확인해 주십시오.
- AV1은 `.ts`에 담지 않습니다. 파일 형식이 `.ts`인 채널이 AV1을 받으면 `.mp4`로 저장합니다.
- 이전 판(0.1.3까지)에는 이 설정이 없어서, 방송이 두 코덱을 함께 내놓으면 먼저 나온 HEVC를 받았습니다. 또 녹화 중에 코덱이 바뀌면 한 파일에 이어 붙여서, 변환은 정상으로 끝나지만 바뀐 뒤쪽이 재생되지 않는 파일이 될 수 있었습니다. HEVC 시험 채널을 녹화한다면 이 판으로 올려 주십시오.

#### 검증 범위와 한계

확인한 것:

- 실제 치지직 채널에서 우선순위대로 H.264 또는 HEVC를 받아 파일로 만드는 것(수십 초 길이).
- 실제 채널에서 한 코덱으로 받다가 다른 코덱으로 이어 받을 때 조각이 빠지지 않는 것.
- 모의 방송에서 녹화 중에 코덱이 바뀔 때 파일을 나누고 알리는 것(받던 코덱이 재생목록에서 사라지는 경우, 같은 재생목록 안에서 바뀌는 경우, 수신이 멈췄다가 다른 코덱으로 다시 붙는 경우).

확인하지 못한 것:

- 몇 시간짜리 실제 방송 전체를 이 판으로 녹화한 결과.
- 실제 방송에서 코덱이 바뀌는 순간.
- 로그인(쿠키)한 상태에서 방송이 내놓는 코덱 구성이 다른지.
- AV1 송출(치지직에서 아직 보지 못했습니다).

코덱을 알아채는 방법과 그 한계:

- 받는 코덱은 방송 정보의 코덱 이름, 재생목록의 코덱 표시(`CODECS`), 조각 앞에 오는 초기화 정보에서 읽습니다. 셋이 다르면 초기화 정보를 따릅니다.
- 녹화 중의 전환은 새 초기화 정보가 오거나, 재생 주소를 새로 받았을 때 받던 코덱이 없어진 것으로 알아챕니다. 새 초기화 정보 없이 영상 내용만 다른 코덱으로 바뀌는 송출은 알아채지 못합니다. 그런 파일은 변환이 정상으로 끝나도 바뀐 뒤쪽이 재생되지 않을 수 있습니다.
- 초기화 정보가 없는 형식(MPEG-TS 조각)의 방송은 재생목록의 코덱 표시만 봅니다. 표시가 없으면 코덱을 알 수 없고, 전환도 알아채지 못합니다.
- 코덱 이름을 알려 주지 않는 플랫폼(유튜브·씨미)에서는 우선순위 설정이 듣지 않고 예전 방식대로 고릅니다.

### 녹화가 도는 방식

- 등록한 채널을 확인 주기(기본 60초)마다 확인합니다. 방송이 시작되면 녹화를 시작합니다.
- 녹화 중인 파일은 이름이 `.part`로 끝납니다. 방송이 끝나면 검증하고 파일 형식을 정리한 뒤(재인코딩 없음) `.part`를 뗍니다.
- 연결이 끊기면 같은 방송에 다시 붙습니다. 이때 파일이 나뉠 수 있습니다.
- 채널 카드에서 "지금 확인", 녹화 시작, 녹화 중지를 직접 누를 수 있습니다.
- 채널 카드에 오류가 보이면 그 까닭(쿠키 필요, 디스크 부족, 연속 실패 등)이 함께 나옵니다.

### 타임머신 (치지직)

치지직은 방송 앞부분을 되감아 받을 수 있습니다. 방송을 늦게 감지해도 설정한 초(0~3600, 기본 3600)만큼 앞에서부터 녹화합니다. 플랫폼이 최근 1시간만 보관하므로 그보다 앞은 받을 수 없습니다. 타임머신이 실패하면 일반 방식으로 바꿔 녹화를 이어 갑니다.

유튜브와 씨미는 감지한 시점부터 녹화합니다.

### 파일 이름

설정 > 녹화의 "파일 이름"에서 패턴을 정합니다. 기본 패턴은 다음과 같습니다.

```
[{date} {time}] {channel_name} {safe_live_title} {record_quality}{frame_rate}{file_extension}
```

| 토큰 | 뜻 |
|---|---|
| `{date}`, `{time}` | 파일을 만드는 날짜와 시각. 모양은 화면에서 고릅니다(기본 `YYYY-MM-DD`, `HHhMMmSSs`) |
| `{recording_time}` | 녹화 시작 날짜_시각(`yymmdd_HHMMSS` 고정) |
| `{broadcast_time}` | 방송 시작 날짜_시각(`yymmdd_HHMMSS` 고정) |
| `{start_time}` | 방송 시작 날짜(`YYYY-MM-DD` 고정) |
| `{channel_name}` | 채널 이름 |
| `{platform}` | 플랫폼(예: `chzzk`) |
| `{safe_live_title}` | 방송 제목(파일 이름에 못 쓰는 글자는 `_`로 바뀜) |
| `{record_quality}`, `{frame_rate}` | 해상도(예: `1080p`), 프레임(예: `60`) |
| `{file_extension}` | 확장자(점 포함) |

화면이 패턴을 바꿀 때마다 예시 이름을 보여 줍니다. 모르는 토큰이나 파일 이름에 못 쓰는 글자(`\ / * ? : " < > |`)가 있으면 저장되지 않습니다. 시각은 한국 시간(KST) 기준입니다.

## 4. 쿠키

공개 방송은 쿠키 없이 녹화됩니다. 연령 제한 방송처럼 로그인해야 보이는 것에만 쿠키가 필요합니다. 쿠키를 넣기 전에 [주의사항의 계정 항목](CAUTIONS.md#로그인-쿠키를-넣을-때)을 읽어 주십시오.

쿠키 탭에서 플랫폼별로 두 가지 방법 가운데 하나로 넣습니다.

- **값을 직접 넣기**: 브라우저 개발자 도구에서 쿠키 값을 복사해 넣습니다.
- **쿠키 파일 올리기**: 브라우저 확장으로 내보낸 `cookies.txt`(Netscape 형식)나 JSON 파일을 올리거나 내용을 붙여넣습니다. 서버가 그 플랫폼에 필요한 쿠키만 골라 저장하고 나머지는 버립니다. 올린 파일 자체는 저장하지 않습니다.

| 플랫폼 | 필요한 쿠키 | 비고 |
|---|---|---|
| 치지직 | `NID_AUT`, `NID_SES` | 네이버 로그인 쿠키 |
| 씨미 | `mauth-authorization-code` | 유효 기간이 약 14일이라 주기적으로 다시 넣어야 합니다 |
| 유튜브 | `cookies.txt` 파일 | 화면이 안내하는 시크릿 창 절차로 내보내야 오래 갑니다 |

저장한 쿠키 값은 화면에 다시 나오지 않습니다. "확인" 단추로 지금도 유효한지 볼 수 있고, 만료되면 알림을 보냅니다.

## 5. 다시보기·클립·영상 받기

다시보기 탭은 확장이 켜져 있을 때 보입니다([8. 확장](#8-확장)).

### 주소로 받기

1. 영상 주소를 붙여넣습니다. 한 번에 10개까지 넣을 수 있습니다.
2. 분석이 끝나면 화질을 고르고 작업을 더합니다.
3. 작업 목록에서 진행률, 속도, 남은 시간을 봅니다.

받을 수 있는 주소는 치지직 다시보기와 클립, 유튜브 영상, 씨미 다시보기와 클립입니다.

### 채널 목록에서 골라 받기

치지직과 씨미는 채널의 다시보기 목록을 모아 두고 고를 수 있습니다.

- 녹화에 등록한 채널은 스스로 목록에 들어옵니다. 다른 채널은 주소나 `@핸들`로 더합니다(모두 합쳐 50개까지).
- 처음 열면 목록 전체를 천천히 모읍니다. 플랫폼에 부담을 주지 않으려고 쪽 사이에 몇 초씩 쉬므로 영상이 많은 채널은 시간이 걸립니다. 그 뒤에는 새 영상만 확인합니다.
- 년·월 단추로 넘기거나 제목으로 찾고, 한 번에 30개까지 골라 받습니다.
- 이미 받은 영상에는 표시가 붙습니다.

### 작업 다루기

- **일시정지와 재개**: 작업 하나씩, 또는 전체를 멈춥니다. 받던 부분을 남겨 두었다가 이어받습니다.
- **다운로드 허용 시간대**: 요일과 시각을 정하면 그 시간에만 받습니다. 시간대가 끝날 때 받던 작업을 멈출지 끝까지 받을지 고릅니다.
- **실시간 녹화 중에는 다운로드를 멈춤**: 기본으로 켜져 있습니다. 어느 채널이든 녹화가 돌면 다운로드를 멈추고, 녹화와 마무리가 끝나면 다시 시작합니다.
- 멈춘 작업에는 멈춘 까닭이 적힙니다. 서버를 다시 시작해도 일시정지 상태는 유지됩니다.
- **조각 동시 받기 수**: 방송 직후의 빠른 다시보기처럼 조각으로 나뉜 영상은 조각 여러 개를 함께 받습니다. 설정 > 다시보기에서 1~16으로 정하고 기본은 4입니다. 권장: 회선이 100Mbps 이하면 1~2, HDD는 2~4, SSD는 4~8, NVMe와 1Gbps 이상 회선이면 8~16. 조각마다 디스크에 확정해 쓰므로 저장소가 느리면 늘려도 빨라지지 않습니다.

## 6. 파일 관리자

파일 탭에서 녹화 폴더 안의 파일을 탐색하고, 이름을 바꾸고, 옮기고, 지우고, 내려받습니다. 폴더를 만들 수 있고 디스크 사용량을 볼 수 있습니다.

- 녹화 폴더 밖으로는 나갈 수 없습니다.
- 녹화 중이거나 마무리 중인 파일과 그 폴더는 잠겨 있어 바꿀 수 없습니다.
- 같은 이름이 이미 있으면 덮어쓰지 않고 거부합니다.
- 삭제는 되돌릴 수 없습니다.
- 설정에서 파일 관리자를 끄거나 읽기 전용으로 둘 수 있습니다.

## 7. 플랫폼 켜기 (유튜브·씨미)

유튜브와 씨미는 처음에 꺼져 있습니다. 설정 화면에서 해당 플랫폼의 "사용"을 누르면 안내 창이 뜨고, 읽고 동의하면 켜집니다. 유튜브는 켤 때 필요한 도구(yt-dlp, deno)가 동작하는지 자체 점검을 합니다.

- 꺼져 있는 동안에는 그 플랫폼의 채널을 더할 수 없고 쿠키 칸도 보이지 않습니다.
- 끄면 그 플랫폼 채널의 감시가 멈춥니다. 채널과 쿠키는 지워지지 않고, 다시 켜면 이어서 감시합니다. 녹화 중인 채널이 있으면 끌 수 없습니다.
- 서버 관리자가 환경변수로 아예 막을 수 있습니다: `LIVE_RECORDER_YOUTUBE=off`, `LIVE_RECORDER_CIME=off`.

### yt-dlp 바꾸기 (유튜브)

유튜브가 바뀌어 녹화가 안 되면 설정의 yt-dlp 묶음에서 "yt-dlp 갱신"을 눌러 새 판으로 바꿉니다. 새 판은 PyPI에서 받고 점검을 통과해야 쓰입니다. 받은 코드는 받는 즉시 점검 과정에서 실행됩니다. 문제가 생기면 설치된 기본 판으로 되돌립니다. 이 기능은 `LIVE_RECORDER_YTDLP_REPLACE=off`로 막을 수 있습니다.

## 8. 확장

다운로드 기능은 확장으로 나뉘어 있고 설정 화면의 "확장"에서 켜고 끕니다. **켜거나 끈 뒤에는 서버를 다시 시작해야 적용됩니다.**

| 확장 | 하는 일 |
|---|---|
| 다운로드 | 작업 대기열, 일시정지·이어받기, 다운로드 시간대, 녹화 중 멈춤. 아래 확장들이 이것을 씁니다 |
| 다시보기 | 치지직 다시보기 받기와 채널 목록 |
| 클립 | 치지직 클립 받기 |
| 유튜브 영상 | 유튜브 영상 받기. 유튜브를 켜야 쓸 수 있습니다 |
| 씨미 다시보기·클립 | 씨미 다시보기·클립 받기와 채널 목록. 씨미를 켜야 쓸 수 있습니다 |

## 9. 텔레그램 알림

1. 텔레그램에서 BotFather로 봇을 만들어 봇 토큰을 받습니다.
2. 알림을 받을 대화의 chat_id를 확인합니다.
3. 설정의 "텔레그램 봇"에 두 값을 넣고 "테스트 전송"으로 확인합니다.

저장한 토큰과 chat_id는 화면에 다시 나오지 않습니다.

| 알림 | 내용 |
|---|---|
| 문제 알림 | 녹화 시작 실패, 비정상 종료(정체, 연속 실패), 녹화 중 영상 코덱 바뀜, 마무리 실패, 디스크 부족으로 녹화 거부, 쿠키 만료 |
| 선택 알림 | 녹화 시작, 녹화 종료(녹화 시간과 파일 이름), 사용자 중지, 마무리 완료 |

알림은 종류마다 켜고 끌 수 있습니다. 같은 채널의 같은 알림은 설정한 시간(기본 300초) 안에 다시 보내지 않습니다.

## 10. 설정 항목

| 묶음 | 항목 | 기본값 | 설명 |
|---|---|---|---|
| 플랫폼별 확인 간격 | 스캔 주기 | 60초 | 그 플랫폼의 채널들을 한 바퀴 확인하는 간격(10~3600초). 30초 이하는 경고합니다 |
| | 채널 사이 간격 | 15초 | 채널 하나를 확인하고 다음 채널을 확인하기까지의 간격. 5초 미만은 경고합니다 |
| 타임머신 | 사용, 되감기 초 | 켬, 3600초 | 치지직 전용 |
| 마무리 | 녹화가 끝나면 파일 형식 정리 | 켬 | 영상·음성은 그대로 두고 파일 형식만 다시 담습니다(재인코딩 없음) |
| | 원본 삭제 | 켬 | 정리가 성공하면 원본을 지웁니다. 실패하면 원본을 `.raw.*`로 남깁니다 |
| | 낮은 우선순위 | 켬 | 정리 작업이 녹화를 방해하지 않게 합니다 |
| 녹화 | 최소 여유 공간 | 5GiB | 이보다 적으면 새 녹화를 시작하지 않습니다 |
| 파일 이름 | 패턴, 날짜·시각 모양 | 위 3절 참고 | |
| 파일 관리자 | 사용, 읽기 전용 | | |
| 화면 | 색 | 자동 | |

채널 수에 채널 사이 간격을 곱한 값이 스캔 주기보다 길면 한 바퀴가 그만큼 늘어나고, 화면이 실제 주기를 알려 줍니다.

### 환경변수

| 환경변수 | 뜻 | 기본값 |
|---|---|---|
| `LIVE_RECORDER_DATA_DIR`, `LIVE_RECORDER_RECORD_ROOT`, `LIVE_RECORDER_LOG_DIR` | 자료, 녹화, 로그 폴더 | [설치 안내](INSTALL.md)의 "자료 위치" |
| `LIVE_RECORDER_HOST`, `LIVE_RECORDER_PORT` | 웹 화면을 여는 주소와 포트 | `127.0.0.1`, `8080` |
| `LIVE_RECORDER_TRUSTED_PROXIES` | 앞에 둔 역방향 프록시의 주소 | 없음 |
| `LIVE_RECORDER_ALLOWED_WEB_HOSTS` | 접속을 받을 도메인 이름(쉼표로 구분). 적으면 그 밖의 이름으로 온 요청을 거부합니다. IP 주소와 localhost는 늘 받습니다 | 모두 받음 |
| `LIVE_RECORDER_MAX_CONNECTIONS` | 동시에 받는 연결 수 | `200` |
| `LIVE_RECORDER_FFMPEG`, `LIVE_RECORDER_FFPROBE` | FFmpeg 도구의 경로 | `ffmpeg`, `ffprobe` |
| `LIVE_RECORDER_ADMIN_USER`, `LIVE_RECORDER_ADMIN_PASSWORD` | 첫 시작 때 관리자 계정을 만듭니다. 만든 뒤에는 지우기를 권합니다 | 없음 |
| `LIVE_RECORDER_SETUP_CODE` | `off`면 첫 설정에서 설정 코드를 묻지 않습니다 | 묻습니다 |
| `LIVE_RECORDER_YOUTUBE`, `LIVE_RECORDER_CIME` | `off`면 그 플랫폼을 켤 수 없습니다 | 켤 수 있음 |
| `LIVE_RECORDER_YTDLP_REPLACE` | `off`면 yt-dlp 바꾸기를 막습니다 | 허용 |
| `LIVE_RECORDER_API_KEYS` | `off`면 접근 키를 쓸 수 없습니다 | 허용 |

## 11. 접근 키와 API

설정의 "접근 키"에서 키를 만듭니다. 권한은 "보기"와 "운영" 둘입니다. 키 값은 만들 때 한 번만 보이므로 그때 복사해 둡니다. 쓰는 방법은 [API 안내](API.md)에 있습니다.

## 12. 명령줄

`vod-recorder`(또는 `python -m live_recorder`) 명령으로 다음을 할 수 있습니다.

```sh
vod-recorder doctor                    # 실행 환경 점검
vod-recorder web                       # 웹 화면과 함께 실행
vod-recorder serve                     # 웹 화면 없이 실행
vod-recorder status                    # 상태 보기
vod-recorder account setup-code        # 첫 설정 코드 다시 보기
vod-recorder account passwd            # 비밀번호 변경
vod-recorder diagnostics               # 진단 묶음 만들기
```

같은 자료 폴더로 서버를 둘 띄울 수 없습니다.

## 13. 문제 해결

| 증상 | 볼 것 |
|---|---|
| 서버가 시작되지 않는다 | `vod-recorder doctor`를 실행합니다. FFmpeg가 없거나 폴더에 쓸 수 없으면 까닭을 알려 줍니다 |
| 첫 설정 코드를 모른다 | `vod-recorder account setup-code` |
| 방송 중인데 녹화가 안 된다 | 채널 카드의 오류 문구를 봅니다. 연령 제한 방송이면 쿠키가 필요합니다. 디스크 여유 공간도 확인합니다 |
| "요청 창구를 멈췄다"는 표시가 뜬다 | 플랫폼이 요청 제한을 걸었습니다. 5~20분 뒤 스스로 풀립니다. 확인 간격을 늘리는 것을 권합니다 |
| 유튜브만 안 된다 | 설정에서 yt-dlp를 갱신해 봅니다 |
| 씨미가 갑자기 로그인 필요로 나온다 | 쿠키가 만료됐습니다(약 14일). 다시 넣습니다 |
| `.raw.mp4` 파일이 남았다 | 마무리 변환이 실패해 원본을 남긴 것입니다. 재생은 대개 되지만 일부 재생기에서 탐색이 느릴 수 있습니다 |
| 다운로드가 시작되지 않는다 | 작업에 적힌 멈춘 까닭을 봅니다. 녹화 중이거나 허용 시간대 밖이면 기다립니다 |
| 확장을 켰는데 탭이 안 보인다 | 서버를 다시 시작합니다 |

먼저 "로그" 탭에서 경고와 오류 줄을 봅니다. 쿠키·토큰 같은 비밀 값은 가려서 보이고, 접속 주소는 그대로 보입니다. 해결되지 않으면 설정의 "로그 내려받기"로 묶음을 만들어 이슈에 올려 주십시오. 올리기 전에 [묶음에 들어가는 것](LOG-EXPORT.md)을 확인합니다.
